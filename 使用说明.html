TrainLog v10 准确营养分析

v10 不再在 AI 未连接或读取失败时生成粗略营养数字。包装食品可使用 App 内的“手动营养表计算”作为可靠后备。

真实 AI 需要在 Cloudflare Worker 中配置 GEMINI_API_KEY 与 TRAINLOG_AI_KEY，然后在 App 的复盘页填写 Worker 地址和同一个密钥，并点击“检查 AI 连接”。

旧版“本地粗略估算”记录会保留为待复核历史，但不会计入今日热量和蛋白质。

TrainLog 使用说明

正式使用方式

想让手机像独立 App 一样使用，不需要电脑一直开着，请把整个 trainlog 文件夹或 TrainLog-PWA.zip 部署到 HTTPS 网站，例如 Cloudflare Pages、Vercel、Netlify 或 GitHub Pages。

部署后，用手机打开 HTTPS 链接，在浏览器菜单里选择“添加到主屏幕”。之后 TrainLog 会像 App 一样从桌面打开。

数据同步

手机和电脑要共享数据，必须有一个云端同步端点。TrainLog 现在已经内置同步面板：

  1. 打开 TrainLog 的“复盘”页面。
  2. 找到“独立 App 与同步”。
  3. 填入同步端点和同步密钥。
  4. 手机点“上传到云端”，电脑点“从云端恢复”，或反过来使用。

没有同步端点时，TrainLog 会本地优先运行，数据只保存在当前设备浏览器里。

云同步端点

输出包里有 cloudflare-sync-worker.js，这是一个轻量 Cloudflare Worker 同步后端示例。部署 Worker 后绑定一个 KV 命名空间，变量名使用 TRAINLOG_KV。部署完成后，把 Worker 地址填到 TrainLog 的“同步端点”。

同步密钥可以自己设置，例如一串随机字符。请不要用生日、手机号这种容易猜到的内容。

启用真实 AI 营养分析

TrainLog v8 的 Worker 已加入多图营养分析端点。它默认优先使用 gemini-3-pro-preview，不可用时回退至 gemini-2.5-pro。包装食品会优先读取营养表并按“每份、每片、每 100g、实际吃了多少”计算；普通饭菜仍属于视觉估算。

  1. 在 Google AI Studio 创建 Gemini API Key。
  2. 部署最新版 cloudflare-sync-worker.js。
  3. 在 Cloudflare Worker 的 Settings → Variables and Secrets 中添加 Secret：GEMINI_API_KEY。
  4. 再添加 Secret：TRAINLOG_AI_KEY，值设为一串只供自己使用的随机密钥。
  5. 在 TrainLog“复盘”页面，将 Worker 地址填入“AI 分析端点”，并将同一串 TRAINLOG_AI_KEY 填入“同步密钥”，然后保存。

不要把 Gemini API Key 写进 GitHub 文件。真实 AI 分析会把你选择的食物照片发送给 Gemini；没有配置端点时，App 会明确显示为低置信度本地粗略估算。

多图与饮食历史

相册上传现在可一次选择多张照片；直接拍照按钮可以连续拍摄并累积。建议包装食品同时提供包装正面、营养表和食用数量。每次按“加入今日”后，会出现在饮食页面底部的历史记录中，并可按日期筛选或删除误记项目。

备份和迁移

如果暂时不部署云同步，也可以在“复盘”页面使用“导出备份”和“导入备份”。这不是自动同步，但可以先让你把手机数据迁移到电脑，或把电脑数据迁移到手机。

开发预览方式

Start-TrainLog.bat 只是开发预览工具：它会让同一 Wi-Fi 的手机临时访问电脑上的 TrainLog。这个模式需要窗口保持开启，不适合正式长期使用。

正式使用请部署到 HTTPS，这样就不需要电脑服务窗口。
